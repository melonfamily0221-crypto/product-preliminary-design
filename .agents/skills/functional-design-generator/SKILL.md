# 功能设计生成器 (Functional Design Generator)

该技能通过检查运行中的 UI 原型，自动生成标准的功能设计 (PRD) Markdown 文档。

## 何时使用此技能
当用户要求“生成功能设计”、“生成功能设计文档”、“根据原型生成 PRD”，或提到基于本地或远程 UI 原型批量生成模块文档时，使用此技能。

## 前置条件
1. 一个可通过 URL 访问的运行中的 UI 原型（例如：`http://localhost:5173/`）。
2. 用户已指定目标模块或页面（例如：“用户管理”）。
3. 指定的 Markdown 文件输出目录以及用于存放截图的 `assets/` 目录。

## 工作流 (Workflow)

### 1. 原型探索（使用 `browser_subagent`）
调度 `browser_subagent` 工具访问目标 URL。为其分配详细任务：
- 使用 `capture_browser_screenshot` 截取主页面截图。
- 读取 DOM 以提取所有搜索字段、按钮和数据表格列。
- 点击主要操作按钮（如“新增”、“修改”、“更多”）以打开弹窗、抽屉或详情页。
- 等待每个弹窗/页面加载，进行截图，并提取所有表单字段和控件。
- 关闭该弹窗/页面，并继续处理下一个。
- 返回有关 UI 布局、控件、字段以及所有已截取图片路径的详尽摘要。

### 2. 资源管理 (Asset Management)
- 使用终端命令将子代理解截取的截图复制到项目指定的资源目录（例如：`docs/assets/`）。
- 确保文件名简洁且具描述性（例如：`user_management_main.png`、`user_add_modal.png`）。

### 3. 文档生成 (Document Generation)
直接引用并严格遵循模板文件 `docs\template-file\2_功能设计.md` 中的设计规范与推导示例，为模块生成 Markdown 文档（例如：`docs/functional-design/{业务模块}/{模块名称}.md`）：

- **严格遵循模板结构**：所有模块必须直接基于 [2_功能设计.md](file:///d:/person/project/20260903-product-preliminary-design/docs/template-file/2_功能设计.md) 中定义的标准层级展开，必须包含：
  - `## 功能描述`：描述模块核心功能与业务目标。
  - `## 业务流程`：包含 Mermaid 流程图（`graph TD`）以及下方的“流程说明：”（含分步序号说明）。
  - `## 功能设计`：按子页面与操作弹窗细化展开。
- **完整输出页面四要素**：各子页面与操作弹窗均严格按照模板规定的四大要素结构编写：
  1. `**1. 页面原型**`：嵌入对应截图，使用相对路径（`![原型说明](../../assets/{截图文件名})`）。
  2. `**2. 功能说明**`：详细说明按钮操作逻辑、业务流转及交互规则。
  3. `**3. 页面控件**`：使用模板标准的五列表格（`| 名称 | 类型 | 位置 | 事件 | 说明 |`）。
  4. `**4. 页面字段**`：使用模板标准的七列表格（`| 名称 | 数据类型 | 长度 | 允许操作 | 是否必输 | 录入方式 | 备注 |`）。
- **推导展开规则**：各一级模块、二级功能页面及操作弹窗均参照模板中的标准示例推导展开。

### 4. 最佳实践 (Best Practices)
- **数据源 (Data Source)**: 始终基于子代理读取的实际 DOM 来确定字段、控件和功能，避免凭空猜测。
- **Mermaid 语法 (Mermaid syntax)**: 确保流程图节点标签中避免使用会破坏 Markdown 语法的特殊字符（例如括号）。
- **图片链接 (Image Links)**: 在 Markdown 中链接截图时，务必使用正确的相对路径（例如：`../../assets/file.png`）。
- **批量处理 (Batch Processing)**: 如果用户请求一次性生成多个模块，请依次顺序处理，以确保子代理能为每个特定模块干净利落地导航和捕获数据。
- **文件编码 (File Encoding)**: 生成 Markdown 文件时，**必须使用无 BOM 的 UTF-8 编码**（`utf-8`，不得使用 `utf-8-sig`）。使用 `write_to_file` 工具直接写入即可满足此要求；若使用 Python 脚本写文件，须显式指定 `encoding='utf-8'`，严禁使用 `encoding='utf-8-sig'` 或任何会在文件头写入 BOM 标记（`\ufeff`）的方式。

### 5. 自检清单 (Self-Check Checklist)
在向用户呈现最终生成的文档之前，Agent **必须**执行以下自检：
- [ ] **结构验证**: 文档是否包含所有必填章节（`功能描述`、`业务流程`、`功能设计`）？
- [ ] **Mermaid 验证**: Mermaid 流程图语法是否正确（例如：节点标签中没有未转义的特殊字符）？
- [ ] **图片资源验证**: 所有截图是否已正确保存在 `assets/` 目录中？Markdown 图片链接是否使用了正确的相对路径格式（`../../assets/xxx.png`）？
- [ ] **表格格式验证**: “页面控件”和“页面字段”表格是否与模板中定义的列头完全一致？
- [ ] **内容完整性**: 在 UI 探索期间发现的所有关键弹窗（新增、修改、详情等）是否都在其各自的子章节和截图中得到了完整记录？
- [ ] **文件编码验证**: 生成的 Markdown 文件是否为无 BOM 的 UTF-8 编码？（可通过检查文件首字节是否为 `EF BB BF` 来确认，存在则代表含 BOM，需重新生成。）
